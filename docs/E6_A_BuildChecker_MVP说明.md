# E6 A：BuildChecker 教学 MVP

目标：把 E5 手工检查转为命令行流程，采集系统调用、解析 Make 数据库、对比实际与声明依赖、输出带证据的 JSON。

## 2026-10-13 助教现场结果

- 镜像 e6-buildchecker:ta1020001；15 项单元测试通过，退出码 0。
- 原始样例检测和构建成功：main.o 缺失 config.h，同时多声明 unused.h。
- 仅修改 Makefile：将 main.o: main.c unused.h 改为 main.o: main.c config.h。
- 修复后检测和构建成功，findings 为空；--fail-on-findings 门禁退出码 0。
- 修复前 trace_id：e6-4059aa0acb084d7399940e3238fbf698。
- 修复后 trace_id：e6-93182d1607284d5b951d80a61bd5e6a8。

结果来自助教实际终端输出；原始证据应导出到 evidence/E6-A。

## 学生交付

1. 实现代码和可执行 full-check 命令。
2. 单元测试及运行结果。
3. 修复前后两组证据：检测报告、实际/声明依赖图、进程归属、Make 数据库、完整 trace、构建日志与源码副本。
4. 修复说明：错误位置、检测证据、修改及复检结果。

构建成功不代表依赖声明正确。缺少 config.h 的声明可能影响之后的增量构建正确性；unused.h 的冗余结论限定于本次构建配置。修复后为空说明本样例中的声明与观测依赖一致。

## 范围与后续验证

这是教学参考实现，支持单个 Make 进程、每个 recipe job 一个最终输出，以成功的读打开调用观测依赖。不能据此声称完成原论文的全部工具或实验。学生须解释进程归属、路径过滤及不支持的情况。

E7 仍需验证故障/不支持输入、门禁拒绝路径及 CI 自动运行。本轮单元测试和正反样例闭环不能替代这些检查。
